## 已确认根因与修正

**根因是主代理验收命令漏掉了 `/v1` 路径前缀。** Miloco 实际保存的是 `http://ai.esxi:18090/v1`，实际请求应为 `/v1/responses`；验收命令却传入 `http://ai.esxi:18090`，使脚本请求 `/responses`。应用模型配置中的 URL 始终保留正确值。

因此，两档 404 数据是无效路由试验，不能用来判断 Grok 8 路或 4 路的能力。此前自动降到 4 路没有解决这类地址错误；正确处理应是停止容量判定并核对完整运行配置。

已完成本地工具修正：

1. 支持 `--runtime-metadata`，从只含完整 `base_url`、`model`、`api_protocol` 的非秘密运行元数据取目标，保留路径前缀。
2. 手工提供的目标与元数据不一致时，在读取 API Key 或发送请求前拒绝。
3. 401/403/404 立即停止继续取新任务，标记 `configuration_error=true`、`capacity_assessed=false` 并返回退出码 2；不得把它自动归类为并发失败再降档。
4. 后续操作必须先核对元数据，再暂停服务；任何工具/配置异常都要先恢复暂停的服务或执行已批准回滚，再处理问题。

修正仅进行了离线测试，**没有再次调用生产模型或重新部署**。
